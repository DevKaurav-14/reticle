### Fixed

- **`@reticlehq/engine` — `stale-response-applied` fired on a page query and its count query that differ only in `page_size`.** Reads that differ only in a parameter that pages through a collection are a fan-out, not a race, but the list of such parameters was matched by exact name: it held `pageSize` and `per_page`, so `page_size` counted as a filter and a passing check became `verified: "no"`. Parameter names are now compared in lower case with punctuation removed, so `page_size`, `page-size`, `pagesize`, `PageSize`, JSON:API's `page[size]` and `per-page` all count, and the list adds `take`, `skip`, `first`, `pageNumber` and `top` (OData's `$skip` and `$top` included). Two reads that also change a filter such as `status` are still reported, and so are reads that differ in `last`, which names a time window. Closes [#1677](https://github.com/reticlehq/reticle/issues/1677).
